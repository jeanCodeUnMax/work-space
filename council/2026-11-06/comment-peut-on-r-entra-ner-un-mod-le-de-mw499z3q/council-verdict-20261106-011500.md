# 🏛️ VERDICT DU CONCILE — Réentraîner / réparer chirurgicalement un LLM

> **Décision** : CONDITIONNEL · **Confiance** : Haute · **Consensus** : 5/6

## ⚖️ Pour / Contre

| Pour | Contre |
|------|--------|
| Édition ciblée (LoRA <1% poids, ROME/MEMIT) = falsifiable, 95-99% benchmarks préservés | Réentraînement global = non traçable, coûteux, détruit les capacités saines |
| Patches prompts/garde-rails = rollback réplicable, diffs mesurables | Chirurgie = présupposé faux : poids distribués, effets non linéaires non localisés |
| Généralisation accrue, modularité des mises à jour (upside) | Généralisation hors distribution <30% après model editing |

## ✅ Avantages / ⚠️ Inconvénients

| Avantage | Impact | Inconvénient | Sévérité |
|----------|--------|--------------|----------|
| Réparation ciblée reproductible | 🟢 | Aucune correction persistante prouvée sans risque de régression | 🔴 |
| Diffs mesurables + rollbacks | 🟢 | Réentraînement sans preuve de réparabilité = panique, pas ingénierie | 🔴 |
| Levier pour nouvelles applications | 🟡 | Malédiction du savoir : opaque pour l'utilisateur | 🟡 |

## 🕳️ Blind spots

- Aucun advisor n'a chiffré le coût d'un pipeline de réparation continue (éval + dataset d'échecs + re-run édition).
- Personne n'a traité le cas « dérive de données » où la chirurgie ne suffit jamais (le modèle n'est pas cassé, le monde a changé).

## 🎯 Recommandation Chairman

Le concil refuse le réentraînement global : intervention chirurgicale uniquement — diagnostic sur prompts critiques → édition ciblée (LoRA/editing) → validation par diffs mesurables + rollback prouvé. Contrariant et Empirique l'emportent : sans traçabilité, pas de scalpel.

**Premier pas (lundi matin)** : constituer le jeu de 50 prompts critiques reproduisant les défaillances réelles, mesurer les écarts avant toute opération.
