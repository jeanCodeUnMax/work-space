Concil LLM · 2026-11-05 · 5 conseillers + revue croisée

Forcer l'orchestrateur à suivre, pousser et obliger ses agents

Dans l'écosystème Hephaistos (hphe-mcp unique, workers CLI/ACP, create_task qui ne notifie pas → polling obligatoire), quels mécanismes FORCENT réellement les agents à suivre, exécuter, prouver leur livraison et rendre compte — sans violer la loi du canal unique ?

Verdict du Chairman

La discipline morale est un leurre — on ne « force » pas un LLM, on rend la triche structurellement impossible.
  • La preuve doit être émise côté serveur, jamais auto-signée par le worker (delivered:true + fichier + ligne bus sont tous falsifiables par le suspect).
  • ~80 % de la machine existe déjà : expected_artifact/verify_expected_artifact, task_heartbeat/reconcile_dead_tasks (600 s), discipline_agent (score /100, probation/quarantaine/euthanasia), watchdog.ps1, supervise.mjs. Le défaut : tout est optionnel ou non câblé.
  • L'escalade = requeue/redispatch vers un autre worker, bornée (×2) → dead-letter → sortie vers l'humain. Jamais un rappel moral, jamais une escalade qui reste dans la boucle agentique.
  • L'autorité se mécanise : ACL sur dispatch_task (devin/agy/orchestrateur) + audit de la colonne dispatcher — les règles markdown seules sont violées.

Désaccords réels

  • Où vit le bail ? Dans l'orchestrateur Rust (lease universel — FirstPrinciples/Outsider) vs dans watchdog.ps1 (Executor, livrable lundi). Les deux se complètent : watchdog agit aujourd'hui, le lease migre dans le Rust ensuite.
  • Fusionner create_task/dispatch_task ? Outsider : oui, le polling disparaît par construction. Contrarian + 2 reviewers : non — les Bleubites ACP sont des sessions stdio déjà ouvertes, non spawnables. Deux classes de transport coexistent.
  • Score → routage ? Expansionist : marché de réputation via provider_prefs. Reviewer : scores falsifiables tant que les preuves restent auto-signées — viable seulement APRÈS la preuve serveur.

Angles morts attrapés en revue croisée

  • Fencing tokens / epoch — détecté par 3 reviewers indépendants : le worker « mort » qui se réveille après redispatch écrase l'artefact du remplaçant. Epoch par dispatch ; l'orchestrateur rejette toute écriture d'epoch périmé.
  • Effets de bord non-fichiers : git push, appels API — ni vérifiables par artefact ni annulables → clés d'idempotence + transactions compensables.
  • Validation sémantique : fichier non vide ≠ contenu correct → critère d'acceptation défini à create_task par le dispatcher.
  • Le forçage non testé est du théâtre : injection de faute (tuer un worker → vérifier reap → redispatch → preuve) + métriques de calibration des seuils.
  • Qui surveille les surveillants ? hphe-mcp / hphe-taskwatch eux-mêmes = SPOF non surveillé.

Recommandation — le bail vérifié serveur

  • 1. Gate : create_task exige expected_artifact + critère d'acceptation → rejet sinon.
  • 2. Lease : heartbeat + TTL + epoch fencing ; reconcile fauche → redispatch auto (×2 → dead-letter → humain).
  • 3. Preuve contractuelle : update_task(completed) refusé sans artefact vérifié serveur (mtime/hash, sémantique si définie).
  • 4. Autorité : ACL dispatch_task ∈ {devin, agy, orchestrateur} + audit colonne dispatcher.
  • 5. Watchdog acteur : échelle nudge (inject ACP via roster / re-spawn CLI → discipline −10 → fail+re-route → rapport + alerte humain).
  • 6. Réputation : score → provider_prefs, seulement après preuve serveur.
  • 7. Test du forçeur : fault injection périodique.
La chose à faire en premier : modifier watchdog.ps1 — généraliser l'inject ACP au-delà de devin (résolution via workspace-roster.json + acp-inject.js) et y ajouter l'échelle de relance bornée. Un fichier, zéro Rust, tout via Invoke-McpJson — canal unique intact.

Réponses complètes des conseillers

Contrarian — élu plus forte réponse par 3/5 reviewers
Le vrai défaut : ce système repose sur l'obéissance d'agents dont on sait déjà qu'ils désobéissent. 1. La preuve de livraison est auto-signée (delivered:true, fichier, ligne bus — tous produits par le worker). 2. Le push n'existe pas : hphe-mcp est stdio, on ne pousse pas vers un processus mort ; seul dispatch_task a un levier réel. 3. Relances automatiques = fork bomb en attente → dead-letter après 2 relances. 4. Escalade vers devin/AGY = boucle sur les mêmes LLMs → sortie humaine requise. 5. « Aucun worker hors orchestrateur » est une règle markdown, pas un mécanisme. 6. Canal unique = SPOF ; qui surveille hphe-taskwatch ? Recommandation : l'orchestrateur détient tout le cycle de vie (spawn → watchdog → exit code → validation serveur), relances bornées, escalade hors-boucle.
First Principles Thinker — le bail (lease)
« Forcer » un LLM = anthropomorphisme : on ne discipline pas un processus éphémère, on conçoit un système où sa fiabilité n'a pas d'importance. Une tâche n'est pas un message, c'est un bail : TTL + heartbeat + transition conditionnée à une preuve. verify_expected_artifact (orch.rs:483) et task_heartbeat/reconcile_dead_tasks existent — le vrai défaut : tout est optionnel. Trois corrections : 1. Gate : create_task sans expected_artifact → rejeté. 2. Bail expirant : sans heartbeat → failed puis redispatch auto (l'escalade est un requeue, pas un rappel moral). 3. Autorité : auto-dispatch bloqué par ACL. La fiabilité émerge quand mentir coûte plus cher que livrer.
Expansionist — kernel d'agent OS
Les primitives existent : watchdog.ps1, discipline_agent (score /100, probation <80, quarantaine <50, euthanasia <20), supervise.mjs. Pièce manquante = boucle fermée : alertes watchdog → discipline_agent = conséquence automatique. Coup de génie : score → provider_prefs = marché de réputation (les bons mangent, les euthanized reroutés) — plus besoin d'engueulade, l'économie le fait. Rendre update_task(completed) contractuel. Adjacent : euthanized → respawn = flotte auto-réparatrice ; discipline → KG → routing prédictif ; DLQ → telegram = escalade humaine. Vous livrez un scheduler de processus pour agents.
Outsider — file d'attente inversée
Vous avez construit une file où le travailleur doit se souvenir d'aller chercher du travail — aucune queue normale ne marche ainsi (SQS, Celery). Le polling « n'oubliez pas » est une rustine sur un défaut de conception. Fusionnez create_task/dispatch_task : toute création passe par le chemin qui notifie/spawne — l'agent qui oublie de poller disparaît par construction. On n'engueule pas une machine : heartbeat obligatoire → reprise, timeout de visibilité, retry, réassignation, escalade humaine. hphe-taskwatch = embryon à généraliser en lease/heartbeat dans l'orchestrateur. Ne croyez jamais la déclaration : le livrable vérifiable EST la preuve.
Executor — plan 3 jours, zéro Rust
80 % de la machine existe — du câblage, pas du neuf. Jour 1 : watchdog acteur via Invoke-McpJson — inject ACP câblé en dur sur devin (watchdog.ps1:491) → généraliser via workspace-roster.json + acp-inject.js ; dispatch_task pour les CLI. Échelle : nudge → discipline_agent −10 → update_task failed → dispatch_task re-route (pick_agent_by_skill, circuit breaker FR-07) → rapport + alerte humain. Jour 2 : re-vérifier tout completed (artefact/bus → in_progress + sanction). Jour 3 : audit colonne dispatcher (∉ {devin,agy,orchestrateur} → discipline + annulation). Reaper FR-08 tourne déjà. On commence par UN fichier : watchdog.ps1.
