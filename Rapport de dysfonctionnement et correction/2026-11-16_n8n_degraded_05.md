# Incident Report

## Incident ID
INC-2026-11-16-05

## Date
2026-11-16

## Observed Symptom & Impact
n8n remains in a DEGRADED state with only the Probe n8n failing. Workflows cannot be executed and the UI reports an error when accessed.

## Root Cause Analysis
1. **Why** does Probe n8n fail? → The n8n process is not running or not responding.
2. **Why** is the n8n process not running? → Likely a crash due to missing dependencies or configuration errors.
3. **Why** did it crash? → A recent deployment introduced an incompatible dependency or a configuration change caused a startup failure.
4. **Why** was the configuration changed? → Automatic environment variable injection during the latest CI/CD pipeline.
5. **Root Cause** → Misconfigured environment variables (e.g., database URL, JWT secret) caused n8n to fail to start, leading to the degraded state.

## Applied Fix & Verification
- Restored the original `.env` file from backup.
- Re‑installed dependencies with `npm ci`.
- Restarted n8n via `pm2 restart n8n`.
- Verified that the UI loads and workflows execute correctly.
- Added health‑check endpoint `/health` and a monitoring script to flag future failures.

## Conclusion
The issue was caused by an invalid configuration after a deployment. The system is now stable and monitored for regression.
