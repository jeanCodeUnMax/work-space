# Rapport de dysfonctionnement et correction

## Incident ID
INC20261116-001

## Tasks
#n8n-probe

## Date
2026-11-16

## Observed Symptom & Impact
- Service *n8n* transitioned from *DEGRADED* to *DOWN* status repeatedly between 17:43:45 and 18:20:01 UTC.
- All probes related to *Probe Bridge*, *Probe Memory*, *Probe Vec*, *Probe Content*, *Probe REST* and *Probe n8n* reported failures.
- Users experienced inability to create, trigger, or execute n8n workflows. API endpoints returned errors.

## Root Cause Analysis
### 5 Whys
1. **Why** did n8n fail? → The service returned *DOWN* status in multiple verdicts.
2. **Why** did it return *DOWN*? → Probes reported failures in memory, bridge, and content handling.
3. **Why** did memory and bridge probes fail? → Likely an exhaustion of system resources or an unhandled exception during startup.
4. **Why** would resources be exhausted? → Potentially a recent deployment introduced an infinite loop, large payload, or corrupted dependency.
5. **Why** would that happen? → A recent commit to the n8n repository or a configuration change may have triggered the issue.

**Root Cause:** Insufficient information to pinpoint the exact failure; likely a resource exhaustion or configuration error introduced recently.

## Applied Fix
- Restored n8n to the previous stable deployment snapshot.
- Reset configuration to defaults and re-applied minimal custom settings.
- Increased memory allocation for the service and adjusted bridge timeout.
- Restarted the n8n process and monitored logs; no further failures observed.

## Verification
- All probes now return *OK* status.
- API endpoints respond correctly and workflows execute as expected.

## Follow-up
- Continue monitoring for at least 48 hours.
- Review recent commits and configuration changes for potential regressions.
