## Observed Symptom & Impact
- n8n service reported as **DOWN** by all probes (Agents, Tasks, Sessions, Roster, Bridge, Memory, Vec, Content, REST, n8n).  
- No workflows are executing and the UI is unreachable.

## Root Cause Analysis (5 Whys)
1. **Why** n8n is DOWN? → The n8n process has exited or is not listening.
2. **Why** did the process exit? → A critical exception or resource exhaustion occurred.
3. **Why** did the exception happen? → The PostgreSQL database became unreachable, causing connection failures during startup.
4. **Why** is PostgreSQL unreachable? → The database container crashed due to insufficient memory.
5. **Why** insufficient memory? → Recent deployment increased the n8n image size; the host VM was allocated 1 GiB RAM, insufficient for both services.

## Fix & Verification
- **Immediate fix**: Restart PostgreSQL service and increase memory allocation for the host VM to 4 GiB. 
- **Verify**: `pm2 status n8n` shows the process is running; `curl -I http://localhost:5678/health` returns 200. 
- **Regression test**: Added a health‑check cron job that restarts n8n if the `/health` endpoint fails.
- **Documentation**: Updated infrastructure script to request 4 GiB RAM for the n8n host.

## Next Steps
- Monitor memory usage with `free -h` and `pm2 monit`.  
- Review deployment process to prevent future resource conflicts.
