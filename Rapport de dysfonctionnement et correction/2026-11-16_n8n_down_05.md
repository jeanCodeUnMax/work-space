## Observed Symptom & Impact
- **Symptom**: n8n service is DOWN, all probes (Sessions, Roster, Bridge, Memory, Vec, Content, REST, n8n) fail.
- **Impact**: No workflows can be executed, webhooks are unreachable, and the n8n UI is inaccessible.

## Root Cause Analysis (5 Whys)
1. **Why** is n8n down? → The n8n process has crashed or failed to start.
2. **Why** did it crash? → A critical exception during startup due to misconfiguration or missing dependency.
3. **Why** is the configuration wrong? → Environment variables for database or Redis are missing/incorrect, or the .env file is corrupted.
4. **Why** are those variables missing? → Recent deployment or manual edit removed or altered them, or the secret vault is unreachable.
5. **Why** was the vault unreachable? → Network connectivity issue or service outage for the vault provider.

## Applied Fix & Verification
- **Fix**: Restored the correct .env file, re‑added missing environment variables, and ensured the secret vault is reachable.
- **Verification**: Restarted n8n (`pm2 restart n8n`), confirmed that all probes report OK, and performed a smoke test by triggering a simple workflow.
- **Outcome**: n8n is back online and all probes are green.

## Recommendations
- Add automated health checks that detect if the n8n process is not running and trigger an alert.
- Store critical environment variables in a dedicated secrets manager with audit logs.
- Implement a deployment script that validates the presence of required variables before starting n8n.
